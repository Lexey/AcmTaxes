﻿# AcmTaxes

AcmTaxes — консольная утилита для расчёта доходов от сделок продажи финансовых инструментов (акции, ETF) в ACM Limited. Она импортирует сделки из брокерских отчётов Excel в локальную JSON-базу и формирует годовой отчёт, связывая продажи с покупками по правилу FIFO.

Результат содержит выручку от продажи и расходы в валюте сделки и в рублях и предназначен для последующей подготовки расчётов для 3-НДФЛ. Утилита не формирует декларацию и не рассчитывает сумму налога. Комиссии в расчёт не входят: в исходных данных они не привязаны к конкретным сделкам.

## 1. Подготовка и сборка

Для сборки нужен .NET SDK 10. Проекты используют целевую платформу `net10.0`; NuGet-зависимости восстанавливаются при сборке. Для получения валютных курсов при формировании отчёта нужен доступ к сервису ЦБ РФ.

Перед запуском настройте лицензию EPPlus в `AcmTaxes/appsettings.json`: параметр `EPPlus:ExcelPackage:License` должен содержать подходящее для вашего использования значение. Для конфигурации `NonCommercialPersonal` после двоеточия указывается имя пользователя. Файл конфигурации копируется в каталог сборки; при запуске тестов используется их `appsettings.json`.

Сборка из корня основной директории:

```powershell
dotnet build AcmTaxes.slnx --configuration Release
```

Для следующих примеров перейдите в каталог приложения. Здесь находятся исполняемая сборка, `appsettings.json` и `NLog.config`:

```powershell
Set-Location AcmTaxes/bin/Release/net10.0
```

## 2. Работа с программой

### Импорт сделок

Команда `import` принимает путь к брокерскому отчёту `.xlsx`. Параметр `--db` задаёт файл базы; по умолчанию используется `transactions.json` в текущем каталоге.

```powershell
dotnet AcmTaxes.dll import "C:\Reports\ACM-2024.xlsx" --db transactions.json
dotnet AcmTaxes.dll import "C:\Reports\ACM-2025.xlsx" --db transactions.json
```

В одну базу можно последовательно импортировать отчёты за разные годы. Для расчёта расходов нужны и покупки прошлых лет, и предыдущие продажи, которые уже израсходовали часть этих покупок.

Повторный импорт полностью совпадающих сделок не меняет базу. Если сделка с тем же идентификатором содержит другие данные, обычный импорт завершается ошибкой. Для замены существующей записи используется `--upsert`:

```powershell
dotnet AcmTaxes.dll import "C:\Reports\ACM-2025-corrected.xlsx" --db transactions.json --upsert
```

### Формирование отчёта

Команда `report` принимает год и путь к выходному Excel-файлу:

```powershell
dotnet AcmTaxes.dll report 2025 sells2025.xlsx --db transactions.json
```

В отчёт попадают продажи указанного года. Более ранние сделки участвуют в восстановлении остатков, а сделки последующих лет исключаются. Генерация отчёта не изменяет JSON-базу.

Используйте новое имя выходного файла: генератор добавляет лист `Продажи ЦБ`, поэтому повторная запись в книгу, где такой лист уже существует, приводит к ошибке.

### Диагностика

NLog выводит сообщения уровня `Info` и выше в консоль, а подробный журнал уровня `Debug` — в `log.txt`. Настройки находятся в `AcmTaxes/NLog.config`.

`Main` перехватывает исключения и записывает их в журнал, но не устанавливает ненулевой код завершения. При автоматическом запуске проверяйте журнал и наличие результата. Прямой вызов публичного `Program.RunReport(ReportOptions)` передаёт исключения вызывающему коду.

## 3. Логика обработки данных

### 3.1. Чтение брокерского отчёта

`OperationsParser` читает лист `Рассчитанные операции`. По умолчанию заголовки расположены в третьей строке. Столбцы определяются по названиям, поэтому их порядок в исходном файле может меняться.

Парсер обрабатывает только строки с операцией `Сделка`. Поддерживаются типы `ПОКУПКА` и `ПРОДАЖА`, единицы измерения `units` и целое количество бумаг. Дата оплаты читается в формате `yyyy-MM-dd`.

Для каждой сделки сохраняются дата, идентификатор, тип операции, сведения об активе, тикер, ISIN, количество, цена, сумма, валюта и номер исходной строки (`SourceIndex`). Цена рассчитывается как `-Total / Quantity`; если её отличие от цены в Excel составляет не менее `0.01`, импорт завершается ошибкой. Также проверяются наличие всех 13 обязательных столбцов и допустимые значения типа операции и единиц измерения.

Настройки листа, заголовков и обозначений операций собраны в `OperationsParserOptions`.

### 3.2. Хранение и объединение сделок

`DB.Database` хранит список объектов `DB.Transaction` в JSON. Отсутствующий файл считается пустой базой.

При сохранении база:

1. Проверяет уникальность идентификаторов внутри импортируемого списка.
2. Сопоставляет новые записи с существующими по `Id`.
3. Пропускает полностью совпадающие записи, добавляет новые и заменяет изменённые только при разрешённом `upsert`.
4. Сортирует результат по дате оплаты и идентификатору и записывает JSON с отступами.

Равенство сделок учитывает все поля записи, в том числе `SourceIndex`. Если изменений нет, файл не перезаписывается.

### 3.3. Распределение покупок по FIFO

`SellReport` группирует сделки по ISIN и упорядочивает их по дате оплаты и идентификатору. Для каждого инструмента создаётся очередь покупок с неиспользованными остатками.

Продажи обрабатываются последовательно. Каждая продажа расходует доступное количество из самой ранней покупки, затем из следующей, пока её объём не будет полностью покрыт. Одна покупка может участвовать в нескольких продажах, а одна продажа — использовать несколько покупок.

Для части покупки, отнесённой к продаже, рассчитываются:

```text
Расходы = -Сумма покупки × Проданное количество / Количество покупки
Расходы в рублях = Расходы × Курс валюты на дату оплаты покупки
```

Программа отслеживает количество, проданное ранее, количество, использованное в текущей продаже, и оставшийся объём покупки. Продажи прошлых лет уменьшают остатки, но не включаются в годовой отчёт.

Если покупок недостаточно или очередная покупка не проходит проверку предшествования продаже по дате и идентификатору, расчёт завершается ошибкой. Полная история сделок важна для корректного распределения расходов.

### 3.4. Валютные курсы

`CurrencyResolver` запрашивает XML с курсами ЦБ РФ на дату оплаты покупки и выбирает валюту по её коду. Поддерживаемые коды заданы в `CurrencyCode`: USD, HKD, AED и CNY.

Полученные значения кешируются в памяти процесса по валюте и дате. Повторные расчёты с той же парой используют кеш. HTTP-запросы выполняются с политикой повторных попыток; отдельного постоянного кеша курсов на диске нет.

### 3.5. Структура выходного отчёта

Результат записывается на лист `Продажи ЦБ`. Продажи сгруппированы по дате оплаты. Внутри каждой группы идут:

1. Строка итогов за дату: сумма продаж и расходы в валюте и рублях.
2. Строки отдельных продаж.
3. Под каждой продажей — использованные покупки с распределёнными расходами и количествами.

Кроме исходных полей сделки, лист содержит столбцы `РАСХОДЫ РУБ`, `ПРОДАНО`, `ПРОДАНО РАНЕЕ`, `ОСТАЛОСЬ`, `РАСХОДЫ` и `КУРС ВАЛЮТЫ`. Группировка строк Excel позволяет сворачивать детали покупок и продаж. Метод `LoadSells` читает структуру отчёта обратно для проверок в тестах.

## 4. Структура решения

Основное решение — `AcmTaxes.slnx`.

| Проект или каталог | Назначение |
| --- | --- |
| `AcmTaxes` | Консольная точка входа, разбор команд `import` и `report`, связывание компонентов. Опции команд находятся в `Options`. |
| `OperationsParser` | Чтение брокерских Excel-отчётов, поиск столбцов и проверка данных сделок. |
| `DB` | Модель `Transaction`, JSON-хранилище, объединение и обновление записей. |
| `CurrencyResolver` | Получение и кеширование валютных курсов; интерфейс `ICurrencyResolver` позволяет подменять источник в тестах. |
| `SellReport` | Распределение покупок по FIFO, расчёт расходов, запись и чтение отчёта Excel. |
| `Tests` | Тесты базы, парсера, расчётов отчёта и валютного сервиса. |

Основные цепочки вызовов:

```text
import → OperationsParser.Parse → Database.SaveTransactions → JSON
report → Database.LoadTransactions → SellReport.BuildReport → Excel
                                             ↓
                                  ICurrencyResolver.Resolve
```

Для работы с Excel используется EPPlus, для JSON — Newtonsoft.Json, для командной строки — CommandLineParser, для журналирования — NLog. Тесты используют NUnit; в тестах расчётов валютный сервис подменяется через Moq.

## 5. Тестирование

Запуск из корня `AcmTaxes`:

```powershell
dotnet test AcmTaxes.slnx --configuration Release
```

Данные базы, парсера и расчётов отчёта расположены в отдельных папках каждого теста:

```text
Tests/
  DbTests/TestData/<имя теста>/
  OperationsParserTests/TestData/<имя теста>/
  SellReportTests/TestData/<имя теста>/
```

Входные данные и ожидаемые результаты хранятся раздельно. Положительные тесты загружают ожидания из JSON; проверки исключений и их сообщений остаются в коде отрицательных тестов. Тесты `CurrencyResolverTests` обращаются к реальному сервису ЦБ РФ, поэтому полный запуск требует сети.
